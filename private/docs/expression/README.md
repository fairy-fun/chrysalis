## SYSTEM ROLE MAPPING — Beat Interpretation Layer

author_beat_view_builder.php
* → Assembler layer
* → Responsible for constructing the author-facing sequence view
* → Does not generate meaning, only composes outputs

character_beat_label_suggester.php
* → Observational interpretation layer
* → Converts applied theme facts into human-readable beat labels
* → Represents what has already occurred (baseline truth)

character_next_beat_suggester.php
* → Predictive interpretation layer
* → Infers likely next beats using narrative_theme_observations
* → Represents forward-looking suggestions (non-persistent, probabilistic)

## PIPELINE POSITION
### Expression Outputs
* → Theme Inference
* → Theme Application (entity_linked_facts)
* → Character Participation
* → Ordered Theme Progression
* → Beat Label Derivation (character_beat_label_suggester)
* → Next Beat Suggestion (character_next_beat_suggester)
* → Author View Assembly (author_beat_view_builder)

### ARCHITECTURAL RULES (LOCKED)
1. Assemblers do not generate meaning.
   They only combine outputs from lower layers.

2. Observational layers operate on applied facts only.
   They must not infer or predict.

3. Predictive layers operate on observation-derived data.
   They must not persist results.

4. Suggestion ≠ truth.
   All forward beats are proposals, never facts.

5. Narrative learning is subject-scoped first.
   Cross-subject influence is weighted and secondary.

## DREAM JOURNAL INTEGRATION — Narrative Theme Learning

Dream journals are first-class narrative sources.

They do not use calendar_event_participants or calendar_event_projection_membership directly. Instead, they emit theme observations into the shared narrative observation layer.

Source-specific extraction:
dream journal entry
→ inferred/applied dream themes
→ narrative_theme_observations

Calendar extraction:
calendar event
→ applied event theme facts
→ narrative_theme_observations

Shared learning layer:
narrative_theme_observations
→ subject-scoped theme progression
→ weighted cross-subject fallback
→ next beat suggestions

## NARRATIVE_THEME_OBSERVATIONS ROLE

narrative_theme_observations is the neutral bridge between source systems and interpretation tools.

It may receive observations from:

- calendar events
- dream journal entries
- prose fragments
- future narrative artefacts

Required fields:

source_type_id
→ identifies the origin system, e.g. source_type_calendar_event or source_type_dream_journal_entry

source_entity_id
→ identifies the source artefact/entity

subject_entity_id
→ identifies the character whose pattern is being observed

projection_entity_id
→ optional book/projection scope

theme_entity_id
→ the applied or inferred theme

sequence_index
→ local ordering signal inside the subject/projection/source stream

confidence
→ confidence or weighting seed for the observation

## HOW OBSERVATIONS FEED THE SUGGESTERS

character_beat_label_suggester.php
→ reads applied theme facts for baseline beat labels
→ should eventually read from narrative_theme_observations for source-neutral baseline views

character_next_beat_suggester.php
→ reads narrative_theme_observations
→ scores likely next themes based on subject-specific transitions first
→ uses cross-subject observations only as weighted fallback

Long-term target:

Both observed beat labels and predicted next beats should derive from narrative_theme_observations so calendar events and dream journals use the same interpretation layer.

## DRIFT AUDIT — Observed vs Predicted Sequence

Purpose:
Detect when predicted next beats diverge from later applied observations.

Audit principle:
Prediction drift is not failure by default.
It is useful signal.

Audit compares:

predicted_theme_entity_id
→ generated by character_next_beat_suggester.php

actual_theme_entity_id
→ later applied into narrative_theme_observations

Audit categories:

MATCH
→ predicted theme equals actual theme

NEAR_MATCH
→ predicted theme is in same cluster/category as actual theme

DIVERGENCE
→ actual theme differs from prediction but may reveal interesting story movement

INVALID_PREDICTION
→ prediction came from bad data, missing scope, or cross-subject contamination

Required invariant:

Predictions must be stored separately from applied facts.

A predicted beat must never become truth unless explicitly accepted/applied.

## LOCKED RULES

1. Dream journals are source artefacts, not exceptions.

2. Calendar events and dream journals feed the same narrative observation layer.

3. Theme learning is subject-scoped by default.

4. Cross-subject pattern influence is opt-in, weighted, and secondary.

5. Predictions are non-persistent unless deliberately logged as predictions.

6. Applied observations remain the only source of baseline truth.

7. Drift between prediction and observation should be audited, not erased.
